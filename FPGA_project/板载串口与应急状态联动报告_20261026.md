## 数据和控制路径

CH340 TXD → B FPGA F12 → RX单bit两级同步 → 有界命令解析 → 按键优先仲裁 → 原B命令状态/序号或原barrier_mode → 原V12 MAC → 原A原子邮箱/应急控制/寻路 → 原场景包14 → 原MAC/邮箱 → B串口状态快照及事件记录。

多位scene/cache/actual均读取已经在net_clk域交付的原数据；没有新增多位像素跨域采样。UART不加入网络包调度、不占用原像素数据口、不等待串口TX才执行原按键/渲染。RX异步端只进入专用rx_meta，后级保持net_clk正常约束。

`OK REQUEST`只表示B接受请求。`REQ`为B请求、`ACT`为A实际回报、`ACK`为原命令序号/状态匹配；`APPLY`为新鲜场景的闭路掩码与请求路障一致。以上都不声称A HDMI已经显示完整新图。原A本地触发的应急不能被UART STOP越权清除；本轮保留此语义，实际状态继续由ACT/ACK反映。
