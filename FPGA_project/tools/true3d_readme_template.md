# HX4S20C 双板蓝色校园 3D 应急地图

本版基于独立保存的透视 3D 地图版，优化蓝色校园材质、中文界面与动态标签，并减少渲染等待。普通图片、持续粒子页、粒子转场和音视频链路保留。原最佳工程与 RAR 独立保存，可用于回退。

## 操作

TF 卡仍插 A，显示器接 A 的 HDMI_B/HDMI2，两板网线直连。卡内素材不需要为 3D 地图更换。

普通模式：PREV_BMP 的 01 → 02 → 03 → 02INFO → 03INFO → 04INFO，之后停留于蓝色实时粒子页。自动播放不回到 01；A S2 短按手动循环六张图片、粒子页、01；A S3 短按暂停/继续。B S2 在普通模式切换 3/5/10 秒周期。

A S4 或 B S4 进入应急：05 → 所选转场 → 06 → 所选转场 → 3D 地图。原应急解除方式保留，解除后恢复普通页面和暂停状态。B S2 应急短按切事件，长按切障碍；B S3 解除远程应急。A 本地应急可用 A S4 切换。

**在 3D 地图已经出现后，A S2 短按**依次切换自动扫视、左视角、中央视角、右视角，左下角显示 VIEW A/L/C/R。应急两张图片播放期间不切镜头。**B 的原缩放拨码**选择 1.00/1.25/1.50，值 3 回到 1.00；左下角显示 Z。人物沿计算路线行走，镜头按人物偏移的一半跟随，以保留校园概览。自动扫视范围为 -60°～-30°；俯仰固定，支持有限旋转，不支持任意 360° 观察。

A S2/S3 长按仍分别调亮度/对比度，长按门限 1.4 秒，不会同时误触短按镜头。A 转场逻辑值 6 使用蓝色粒子淡变，0～5 和 7 的原特效保留；请以屏幕/数码管确认拨码逻辑值。

## 两板分工与画质

A 承担 Dijkstra 寻路、路线节点存储、人物沿路线行走，并用共享乘除法计算 XYZ 旋转、透视除法、倒深度、缩放和人物跟随。B 只上报缩放拨码、障碍设置和已收到的实际应急状态。A 直接将本地路线结果交给投影器，不再让完整场景先从 B 往返传输。B 接收带帧号的 118 个投影三角形，用 8 行 BRAM 瓦片完成覆盖、16 位倒深度测试、建筑侧面/窗格、道路流光、红色危险建筑、白色人物和出口标记，加上中文标题、图例、危险/人员/路线标签和旋转指南针，再写入既有 SDRAM 地图区域，游程编码传回 A。A 收齐整帧后在视频场边界切换双缓冲并叠加 OSD、输出 HDMI。

A 使用固定校园图的精确 5 位距离编码：176 单位的普通道路记为 2，80 单位的终点出口支路记为 1。路径的真实代价为 n×176 或 n×176+80，与 2n 或 2n+1 的排序、相等关系一致；出口为度数 1 的终点，不继续扩展。13,546 组 RTL 对照验证保留原 Dijkstra 的路线、方向、出口、节点链和逐周期行为。此编码只适用于当前固定边权；生成程序会检查原边权表达式，改图时必须重新评估。

这是实时三角形渲染，包含透视和前后遮挡；没有把参考图片当作地图背景。采用低多边形、蓝色道路、分层窗格和实色面，不能达到参考图的摄影纹理、烟雾和光照细节。地图原生 320×180，B 复制成 640×360 传输，A 放大至 1280×720；输出分辨率不代表原生渲染精度。

TF 仍由 A 读取物理 SPI 扇区、转发给 B；FAT/BMP 解析、缩放、源图片缓存和图片传输仍在 B。现有频谱与轮播周期计时保留在 B，地图的寻路和行走计算已迁到 A。地图与蓝色粒子互斥复用 B 的同一帧缓存，A 继续使用两个完整地图接收缓冲，无新增 SDRAM 预留。A 共预留 2073600 个 32 位字，B 共预留 1958400 字，各板容量 2097152 字。

当前有限镜头范围内全部顶点带保守取整余量仍落在 -104～424。B 使用 10 位有符号坐标、22 位边函数和 36 位串行梯度除法减少逻辑；线上坐标仍为 12 位，超出支持范围的三角形在截位前直接拒绝。没有降低几何精度或改变本场景渲染结果。

B 用四个像素对的输出队列隔离 SDRAM 写 FIFO 的背压与 UI 字库取址。队列占用量决定下一像素取数，外部 ready 不再穿过字库地址组合链；最后一个像素出队后才发布整帧完成。逐像素、背压、断网取消和完整帧缓存链路均做回归。

A 的轮播、按键、缓存页面管理和对应邮箱使用现有 25MHz 网络控制时钟，毫秒、按键和轮播周期参数同步校准；物理 TF SPI 仍使用原 100MHz 时钟。SDRAM、视频和音频时钟保持原配置。

地图目标上限 30 帧/秒。完整缓存链路三个视角的仿真提交时刻为 33.38、66.64、116.54ms，相邻间隔约 33.27/49.90ms；复杂或放大场景可能降至约 20 帧/秒。B 单独三帧渲染约 12.0/12.6/14.8ms。连续预览 GIF 按 33ms/帧组织，**这些是仿真，不是实板 FPS 测量**。当前网格 324 个镜头/事件/人物/光流样本中，30fps 的 B 最大采样地图线速需求约 46.51Mbps；地图预算 55Mbps。计入最多约 34.86Mbps 的物理 TF 封包、几何及其确认、64 样本频谱、控制快照和心跳后，两方向各按 95Mbps 预算；B 采用地图 55Mbps 预算时合计约 92.79Mbps，A 的采样地图确认上界合计约 91.82Mbps（全双工方向分别计算）。图片与重传共享剩余仲裁带宽，背压会降低饱和时的 TF 吞吐和地图帧率，不保证所有链路同时满速或任意复杂场景恒定 30 帧。

断网时丢弃未完成场景和半帧，A 保留最后完整画面，不自动解除应急；重连后重新上传场景。B 每 20ms 或设置变化后上报控制快照，A 拒绝旧序号、格式错误和应急状态不匹配的控制；超过 500ms 没有有效快照时停止产生新地图场景。控制报告按 50Hz 计算约占 0.034Mbps。粒子和地图缓存的所有权持续到 A 的最终确认，避免覆盖正在传输的帧。实板冷启动、实际帧率、显示器音频恢复、温度和功耗仍需上板验证，未测量的项目没有标成已通过。
