# 粒子画面进出翻牌/缩放转场候选

从当前温度叠加版另存，解决手动进入粒子渲染、从粒子返回普通图片时硬切的问题。A板转场拨码1=翻牌、2=居中缩放；两个方向均使用原有17阶段。原主FX关闭拨码sw[3]仍可明确选择硬切，其他转场保持原行为。正常自动进入粒子时同样使用所选过渡，不增加新的播放操作。

## 烧录

已配套使用temperature_osd_20261030两板固件的，只PROGRAM_FLASH本包firmware/A_display_3V3.bit；B板程序逐字节不变，无须重刷。较早版本或不确定版本时，配套PROGRAM_FLASH本包A/B。烧录后拔掉包括USB在内的全部供电约5秒，再两板一起上电。TF、HDMI继续接A，串口接B，115200/8N1；卡素材、接线和PC工具不改。

## 行为

- 最后一张普通静态图之后的粒子启动步骤仍保留；进入粒子时，等完整粒子帧到达后再开始过渡，不显示半帧。暂停时首次粒子帧仍按原机制准备，完成后保持用户的PAUSE状态。
- 翻牌收拢旧画面、展开新画面；缩放在旧完整画面上展开新画面。粒子端使用完整的RGB444帧，普通图片使用原RGB888缓存；复用原行缓冲和转场计算，没有新增帧存储、RAM块、DSP或时钟。
- 过渡期间保持参与显示的粒子缓存不被新完整帧替换，ACK和双缓冲交换一起暂缓。过渡结束后恢复动态提交。正常粒子双缓冲更新不反复触发转场。
- 静态页码在原分辨率提交toggle的三级同步资格到达后采样，动态槽本来就在视频域。不同步逐位页码，不把未提交的源总线变化当新页面；25MHz源/75MHz视频的提交与未提交干扰回归通过。
- 转场中继续按下一张时，当前旧/新画面对保持完整，再处理最近提交的目标；粒子退出与随后图片切换都完成过渡。连按可能合并到最后提交目标，保持原控制器的最新目标语义，不承诺每次按键都排成无限队列。
- 应急到来时仍在原帧边界取消普通转场，解除粒子缓存暂缓，保留应急优先和本地告警所有权。原应急提示、地图跟随、路障、寻路、字幕、音源与可视化不改。
- 左上角TEMP实时温度、45/55/50℃三样本策略、故障保锁、人工解除后独立STOP，以及3/5/8秒普通轮播均继承温度版。
