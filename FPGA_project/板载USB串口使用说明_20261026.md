# B板USB串口使用说明

本包是uart_service_20261026候选，从唯一最佳follow_view另存。原最佳未覆盖；原独立map_flow流畅度候选未合并。

## 烧录与连接

若A已经运行最佳follow_view的2F3F2781…固件，只需PROGRAM_FLASH本包 `firmware/B_control_3V3.bit`。A版本不确定时使用包内A/B配套。TF仍插A，图片与音乐不改；两板完全断电约5秒后一起上电。

USB线接**B板板载USB转串口/CH340接口**，不是只接JTAG下载口。终端选择该CH340的COM端口，115200、8数据位、无校验、1停止位、无硬件流控。发送ASCII大写命令，以LF或CRLF结束。每次等完整响应再发下一条；仅CR不会执行，1秒后报超时。命令最长16个字符，不含换行。支持LF/CRLF，不支持中文命令和二进制协议。

手册 `D:/HX4S20开发板手册-HDL版2410.pdf` 第11页图2-10及管脚表核对：CH340 TXD对应网名RXD、FPGA F12为接收；CH340 RXD对应网名TXD、FPGA D12为发送。无需外接USB转TTL模块。手册与最终IO报告匹配，实际串口尚待上板。

## 常用命令

| 命令 | 用途/响应 |
|---|---|
| `PING` | 返回PONG，验证串口 |
| `HELP` | 一行命令摘要 |
| `STATUS?` / `GET STATUS` | 返回一行状态快照 |
| `DEMO FIRE` | 请求火灾应急，STATE=1 |
| `DEMO QUAKE` | 地震，STATE=3 |
| `DEMO LAB` | 实验室事故，STATE=5 |
| `DEMO DRILL` | 演练，STATE=7 |
| `DEMO STOP` / `NORMAL` | 请求退出，STATE=0 |
| `BARRIER SET 0` | 原无附加封路档，事件本身危险边仍关闭 |
| `BARRIER SET 1` | 原一处附加封路档 |
| `BARRIER SET 2` | 原两处附加封路档 |
| `BARRIER SET 3` | 原全部四出口关闭档，预期无路 |
| `LOG READ 16` | 导出最近16条；可用1～64，超过实际条数按实际输出 |
| `LOG CLEAR` | 清除日志及LOST，不清除应急/路线/REV |
| `TEMP?` / `GET TEMP` | 返回ERR SENSOR_NOT_INSTALLED；尚无温度传感器 |

正常演示：PING → STATUS? → DEMO FIRE → STATUS?直到ACT=1、ACK=1、FRESH=1、APPLY=1 → BARRIER SET 2 → STATUS?直到BAR=2、APPLY=1 → BARRIER SET 3观察无路 → LOG READ 16 → DEMO STOP。

`OK REQUEST STATE=1`仅表示B接受请求；地图完整显示仍看显示器。断链时控制返回ERR LINK_OFFLINE。普通模式不能设置路障，返回ERR NOT_EMERGENCY。同拍按键优先，串口返回ERR KEY_PRIORITY。忙时完整新命令不会执行，之后最多补一条ERR BUSY；主机应逐条请求/应答，不要连续粘贴整段脚本。

A本地按键触发的应急保留原所有权保护，串口STOP不强行清除。此时REQ=0、ACT=1、ACK=0可持续出现；用A原按键解除。离线不自动撤销既有应急。拔USB不停止原FPGA系统。

## 状态解释

数值均按十六进制打印（MS/AGE显式0x前缀）；单bit/事件0～7读法相同。例如LOG=40表示64条，不是40条十进制。

| 字段 | 含义 |
|---|---|
| MS | 上电后毫秒，32bit，约49.7天回绕，不是日历时间 |
| REQ / ACT | B请求 / A最后回报状态；0正常、1火灾、3地震、5实验室、7演练；ACT仅LINK=1时可认为在线 |
| BAR | B原路障请求0～3 |
| ACK | 原命令序号与实际状态均匹配，不代表地图或路障已画完 |
| APPLY | 新鲜场景闭路掩码符合当前事件+BAR；不是HDMI完整显示确认 |
| SRC | B最近操作来源，1串口、0原按键/复位；ACK=0时不能据此断言A实际告警来源 |
| LINK | 原协议双板在线资格 |
| PHY | 原PHY已完成配置；不是额外的实时线缆检测字段 |
| CACHE | B原缓存角色位图，FF表示八角色缓存有效；不能证明TF目前在位/健康 |
| FAULT | 原B存储source_fault编码，0正常，非0需结合原链路诊断；没有新造TF故障分类 |
| FRESH / AGE | 收到匹配实际事件且未满1000ms的场景 / 距最近场景毫秒；无有效场景AGE=FFFFFFFF，断链立即失效 |
| EXIT | 原出口1北、2西、3东、4南；正常/无路/数据无效时0 |
| CLOSED / ROUTE | 原16边闭路/路线位图；FRESH=0时仅为历史值 |
| REV | 不同已接收应急路线签名累计数，饱和FFFF；不把镜头/引导点运动计成重规划，不等于求解器执行次数 |
| LOG / LOST | 已保留条数 / 因64条环形覆盖或同类待写覆盖累计丢失数，LOST饱和FFFF |
| RXERR | 接收帧错误累计数，饱和FFFF |
| SENSOR | 固定NONE，尚无传感器 |

## 日志

输出LOG COUNT=HH、若干 `MS=0x........ TYPE=HH CTX=HH DATA=HHHH`、END LOG。按循环库追加顺序导出最近N条，旧→新；同拍类别共享时间，不保证严格时间排序。64条快照复制完成后继续记录新事件，导出内容不随环形覆盖改变。LOG CLEAR与断电会丢弃记录，无写TF/RTC。

TYPE：01启动、02在线、03离线、04缓存/源故障变化、10演练请求、11退出请求、12路障请求、20观察到实际状态变化、30～34收到不同路线结果（末位为出口0～4）、40场景失效、50命令拒绝、60串口帧错。

CTX：[7:6]来源0按键/1串口/2未确认，[5:3]A状态，[2:1]B路障，[0]最近no_path。TYPE10～12为请求上下文，其余为采样时上下文。DATA：04为高4bit空、FAULT4bit、CACHE8bit；10/11/12为请求事件或路障值；20为实际状态；30～34为CLOSED位图；50为拒绝原因；60为错误前RXERR计数。来源是B已确认命令上下文，不能识别所有A本地/外部原因。

50原因十进制编码：0未知命令，1非法/超长行，2范围，3忙，4离线，5不在应急，6超时，7帧错，8按键优先，9未装传感器。导出DATA仍为十六进制。

## Windows单命令辅助工具

终端也可直接使用 `tools/uart_console.ps1`（标准SerialPort，无额外Python库）：

```powershell
powershell -File .\tools\uart_console.ps1 -Port COM5 -Command "PING"
powershell -File .\tools\uart_console.ps1 -Port COM5 -Command "DEMO FIRE"
powershell -File .\tools\uart_console.ps1 -Port COM5 -Command "STATUS?"
powershell -File .\tools\uart_console.ps1 -Port COM5 -Command "LOG READ 64" -SaveTo .\event_log.txt
```

COM5只是示例，应替换B板实际端口。不要同时用串口助手占用该COM。工具不自动重试控制命令，避免重复触发。辅助工具已做语法静态核验，实际COM通信待上板。
